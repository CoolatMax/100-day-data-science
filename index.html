Execution Rules

  • Every day ships: one notebook/script, one small output artifact, one README update, one Git commit and one LinkedIn-ready sentence pair.
  • Prefer physical meaning: every feature should have a reason tied to energy production, equipment health, telemetry behavior, location or operating regime.
  • Model honestly: use time-aware/group-aware/spatial validation whenever random splitting would leak information.
  • Build a portfolio, not 100 disconnected notebooks: every 10–20 days, consolidate the best work into a versioned project release.
Best portfolio outcome: finish with one capstone repository and one alternate-domain project so the portfolio proves both transferable ML capability and industry-specific depth.
